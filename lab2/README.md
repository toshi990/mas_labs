# Распределение заказов

Лабораторная работа №2 по теории многоагентных систем.
Сравниваются централизованное назначение венгерским алгоритмом, контрактная сеть и аукцион заявок.

## Запуск в PyCharm

Открыть папку `mas_labs`, выбрать интерпретатор Python 3.10 или новее и запустить `main.py`.
Параметры вводятся в окне Run. Сторонние библиотеки для модели и экспериментов не нужны.

Из терминала папки проекта:

```bash
python3 main.py
```

Главное меню:

1. Пошаговая симуляция: выбрать сценарий и механизм, затем смотреть состояния, заказы и сообщения.
2. Сравнение трёх механизмов: один набор заказов выполняется всеми способами.
3. Серия экспериментов: четыре сценария на заданном количестве seed.
0. Выход.

В списке сценариев пункт 5 открывает ввод количества складов, мест погрузки, курьеров и параметров заказов.
Enter оставляет значение по умолчанию.

## Первое сравнение

Запустить `main.py` и последовательно ввести:

```text
2
1
42
```

Будут показаны время завершения, своевременность доставки, опоздания, пробег и стоимость обмена для трёх механизмов.
Результаты и полные сообщения этого сравнения сохраняются в `output/comparison.json`.
Для выхода ввести 0.

Для наблюдения за агентами выбрать в главном меню 1, сценарий и механизм.
В меню симуляции 2 выполняет одну минуту и показывает сообщения; 1 показывает склады и курьеров;
4 показывает заказы; 5 — последние сообщения; 6 выполняет все заказы; 8 сохраняет трассу.
У готовых сценариев должно быть доставлено 40 из 40 заказов.

## Полная серия

```bash
python3 run_experiments.py
```

Используются четыре сценария, seed от 0 до 29, три механизма и три повторения для замера времени.
Всего 360 вариантов «сценарий — seed — механизм», 1080 выполнений.
Одинаковые входные данные передаются механизмам копированием одного набора заказов.

Короткая серия в отдельную папку:

```bash
python3 run_experiments.py --seeds 3 --repeats 1 --output output/quick
```

Можно указать отдельные сценарии через `--scenarios normal burst loading heterogeneous`.

## Результаты

В `results/lr2` находится серия, использованная в отчёте:

| Файл | Содержание |
| --- | --- |
| `runs.csv` | Показатели каждого из 360 прогонов |
| `summary.csv` | Средние и стандартные отклонения по 30 наборам |
| `inputs.json` | Конфигурации и все исходные заказы |
| `paired_differences.json` | Парные различия механизмов на одинаковых заказах |
| `sample_traces.json` | Примеры полных трасс для seed 0 в каждом сценарии |
| `metadata.json` | Параметры серии, версия среды и хеш исходников |

Основные показатели: модельное время завершения, средняя длительность доставки, среднее опоздание по всем заказам,
доля своевременных доставок, пробег, ожидание погрузки, число сообщений и их объём в UTF-8 JSON.
Сообщения распределения считаются отдельно от погрузки и сообщения о доставке.
Время распределения в миллисекундах измеряется на компьютере и не увеличивает модельное время.
Оно может различаться при повторном запуске; модельные результаты при одинаковом seed повторяются.

## Устройство

| Файл | Назначение |
| --- | --- |
| `main.py` | Консольный запуск |
| `run_experiments.py` | Запуск серии из терминала |
| `mas/model.py` | Агенты, заказы, доставка, обмен и показатели |
| `mas/allocation.py` | Три механизма и венгерский алгоритм |
| `mas/network.py` | Карта и кратчайшие пути |
| `mas/config.py` | Настройки и их ограничения |
| `mas/scenarios.py` | Четыре экспериментальных сценария |
| `mas/experiments.py` | Сравнение, агрегирование и сохранение результатов |
| `mas/console.py` | Ввод, меню и вывод |

Оценка пары одинакова: время пути на склад и к получателю, погрузка и передача заказа.
Очередь склада и срок заказа в оценку не входят.
Централизованный механизм ищет максимальное число назначений с минимальной суммарной оценкой.
Контрактная сеть последовательно объявляет заказы и выбирает лучшую оценку курьера.
В аукционе каждый свободный курьер выбирает один заказ, после разрешения конкуренции проигравшие участвуют снова.

## Проверки

```bash
cd lab2/
python3 -m unittest discover -s tests -v
```

Проверяются венгерский алгоритм полным перебором на малых матрицах, различия трёх правил назначения,
вместимость, очереди, одинаковые входные данные, повторяемость, подсчёт сообщений и запуск консоли.
